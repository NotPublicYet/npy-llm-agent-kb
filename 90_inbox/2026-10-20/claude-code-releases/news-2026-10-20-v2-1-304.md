## Summary
<h2>What's changed</h2>
<ul>
<li>Added a transcript line when a plugin that runs first skips one of your mod's hooks, naming the event and the plugin</li>
<li>Added <code>decider: "person"</code> to a mod's <code>tool.check</code> answer: only the permission dialog or a host's callback can approve the ask, and it is refused with the mod's reason where nobody can be asked</li>
<li>Added <code>e.isReadOnly</code> to a mod's <code>tool.check</code> event, set when the tool call is read-only</li>
<li>Added <code>/auto-mode-setup</code>: a guided setup that reads your project and recent sessions to teach auto mode about your environment, now also available on Bedrock, Vertex, Foundry, Claude apps gateway and telemetry-disabled sessions</li>
<li>Added <code>/claude-api managed-agents-secure</code>, which compares a Managed Agents agent's settings with Anthropic's published security guide, without changing anything</li>
<li>Added the names of the tools called earlier to the compaction summary in the transcript view (Ctrl+O)</li>
<li>Added a warning on Pro and Max plans when resuming an inactive conversation would use a noticeable share of your 5-hour usage limit: resume anyway, or start a new conversation and Claude can look up the previous one if you refer to it</li>
<li>Fixed the organization policy not refreshing until the hourly check after approving an <code>ANTHROPIC_API_KEY</code> at startup or switching "Use custom API key" in <code>/config</code></li>
<li>Fixed sandboxed commands failing to start on Linux when a <code>sandbox.filesystem.denyRead</code> glob contains brackets that are not a character class, such as a <code>[user-id]</code> route folder</li>
<li>Fixed <code>rm -r</code> of a mounted drive or a folder at its top level (<code>/Volumes</code>, <code>/media</code>, WSL's <code>/mnt/c</code>) not getting the safety prompt that <code>rm -rf /Applications</code> gets</li>
<li>Fixed <code>CLAUDE_CODE_TRANSCRIPT_LOCAL_GC</code> dropping messages from the saved transcript when the disk filled up while the file was being trimmed</li>
<li>Fixed a plugin keeping a headless run going past <code>--max-turns</code>, Stop, or ended input by spawning subagents or re-running a finished one</li>
<li>Fixed a failed mod reload removing the tools and commands of the version that stays loaded, and its messages being wrong or silent about whether the previous version is still loaded</li>
<li>Fixed a click on a mod's button being lost when buttons with the same label and no <code>key</code> were redrawn unchanged</li>
<li>Fixed mod sharing in the built-in <code>plugin-authoring</code> skill stopping at the secret scan on machines with managed settings and on Team and Enterprise plans</li>
<li>Fixed scheduled Cowork cloud sessions waiting five minutes again for each subagent whose WebFetch needed a URL approval that nobody was there to give</li>
<li>Fixed Write results and rejected edits showing a file outside the working directory as <code>../../…</code>; they now show <code>~/…</code> or the full path</li>
<li>Fixed a claude.ai Directory plugin's skills not running as commands when picked from the "/" menu in Cowork cloud sessions</li>
<li>Fixed Remote Control permanently withholding a desktop conversation's history when a different account was signed in to the terminal</li>
<li>Fixed Remote Control failing to start from Claude Desktop when DISABLE_TELEMETRY or DO_NOT_TRACK is set on a paid plan</li>
<li>Fixed model switches, messages and interrupts waiting behind a context usage check in SDK and desktop sessions</li>
<li>Fixed <code>context_management: Extra inputs are not permitted</code> errors behind LLM gateways; Claude Code now resends the request without that field</li>
<li>Fixed OpenTelemetry settings delivered through server-managed settings being ignored for the whole session after signing in during first-run setup or the first start after /logout</li>
<li>Fixed unsandboxed Bash commands in Claude Desktop Code tab sessions on macOS and Linux not seeing environment variables exported in shell startup files such as ~/.zshrc</li>
<li>Fixed the Consumer Terms notice being skipped for a day or longer after a server error</li>
<li>Fixed <code>/privacy-settings</code> offering choices that may not apply to you after a network or server error</li>
<li>Fixed a "Context limit reached" or "Prompt is too long" error after stopping a turn while Claude Code was compacting a conversation the API had rejected as too long</li>
<li>Fixed subagents sometimes forgetting their most recent work when they were messaged or resumed right after finishing</li>
<li>Fixed <code>claude --help</code> text for <code>--tools</code>, <code>--resume</code>, <code>--debug</code>, <code>--json-schema</code>, <code>--disable-slash-commands</code>, <code>--system-prompt-snapshot</code> and <code>claude update</code> to match actual behavior</li>
<li>Fixed <code>claude --worktree</code> removing the worktree and its branch without asking at exit when HEAD was detached or on another branch, which could lose commits</li>
<li>Fixed resumed and cloud sessions sending Claude the whole skill list again each time plugins reloaded at startup</li>
<li>Fixed an interrupt not ending a Read that waits on an idle pipe or device named like an image</li>
<li>Fixed <code>/effort status</code>, <code>/effort ultracode</code> and the prompt's effort indicator showing a guessed effort level when <code>CLAUDE_CODE_EFFORT_LEVEL</code> is <code>auto</code> or <code>unset</code> and no level is sent</li>
<li>Fixed a PreToolUse hook's deny reason being replaced by a timeout error when an Agent SDK callback hook on the same tool call timed out</li>
<li>Fixed Bash and PowerShell deleting a large command's output file when it could not be copied to the session's tool-results folder, unless the disk is full</li>
<li>Fixed notes typed into a multiple-choice question with previews being cut off with "…" in terminals under about 100 columns, hiding what was typed (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5025726790" data-permission-text="Title is private" data-url="https://github.com/anthropics/claude-code/issues/82768" data-hovercard-type="issue" data-hovercard-url="/anthropics/claude-code/issues/82768/hovercard" href="https://github.com/anthropics/claude-code/issues/82768">#82768</a>)</li>
<li>Fixed self-paced <code>/loop</code> wakeups scheduled at the 1-hour maximum firing just after the 1-hour prompt cache expired, so those wakeups no longer re-read the conversation uncached</li>
<li>Fixed agent teams: approving a shutdown request from the main session no longer exits the whole CLI</li>
<li>Fixed a skill's <code>once</code> hook also removing another skill's identical hook after it ran</li>
<li>Fixed transcript mode's <code>{</code> and <code>}</code> landing the prompt on an inconsistent row, or off screen, instead of the transcript's first row</li>
<li>Fixed <code>CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k</code> silently setting a 100K window: the variable now accepts <code>k</code> and <code>M</code> suffixes like <code>--autocompact</code>, and warns when a value is out of range or ignored</li>
<li>Fixed Ctrl+C in the agents view clearing a text selection without copying it when pressed before the mouse button was released</li>
<li>Improved <code>/usage</code> to say when a rate limit on usage data ends instead of "try again in a moment"</li>
<li>Improved the lines shown when a mod written in the session loads, reloads or fails to load</li>
<li>Improved artifacts with several views: when you ask for links to them, Claude now writes out each view's link and explains that the address bar stays the same as you switch views</li>
<li>Improved cloud sessions: a new conversation's first turn no longer waits for the local (stdio) MCP servers of plugins synced from claude.ai, unless a server sets <code>alwaysLoad: true</code></li>
<li>Improved how a remote session recovers its status when the server refuses a status update that carried other session data</li>
<li>Improved session file size in auto mode: the safety classifier's context is no longer stored with every request</li>
<li>Improved the <code>claude -p</code> invalid-settings warning: a file that did not load lists only what stopped it, and long lists are capped per file</li>
<li>Improved resume of large compacted sessions in SDK and headless mode: the first request after resuming is sent sooner</li>
<li>Improved responsiveness and throughput when many subagents are running at the same time</li>
<li>Improved memory use when sending requests in long or resumed conversations</li>
<li>Self-hosted runner: Improved the error shown when the git host answers "not found" for a session's repository: it now names the repository and whom to ask</li>
<li>Windows: Improved git command start-up with a standard Git for Windows install by running its git.exe directly instead of through its cmd launcher</li>
<li>Changed mods' <code>settings.read</code> hooks to receive each settings layer and rewrite the merged settings, so a managed mod can make an organization's setting a ceiling, including the <code>cleanupPeriodDays</code> the retention sweep uses</li>
<li>Changed the <code>/artifacts</code> delete confirmation to show numbered choices: 1 or Enter keeps the artifact, 2 deletes it, and y, n and Esc still work</li>
<li>Changed the question that turns on the mods Claude writes in a session to plain text with no link or session id; it stays up when a new turn starts, and Claude tells you what loaded when you turn them on</li>
<li>Changed tool search to be on by default behind a custom <code>ANTHROPIC_BASE_URL</code>; a 400 or 422 from the gateway is retried without it</li>
<li>Changed compaction to send Claude the skill list again afterwards; <code>/reload-skills</code> now sends only new or changed skills</li>
<li>Changed skill hooks: the skills of one source (a repo, your own folder, or a plugin) can register at most 1,024 hooks and 16,384 matcher characters per session</li>
<li>Changed skills under a policy that allows hooks from plugins only: a skill used in the main conversation whose hooks are kept out no longer gets its <code>allowed-tools</code></li>
<li>Updated the /claude-api skill to use the <code>ant</code> CLI on Claude Platform on AWS instead of falling back to the SDK or curl</li>
<li>Removed the notes from <code>claude plugin validate</code> that predicted where a mod's hooks would run</li>
<li>Removed the "(research preview)" label from the <code>/fast</code> dialog title on Opus 5.5</li>
<li>[VSCode] Added mod drawing in the chat panel for sessions on Amazon Bedrock, Google Vertex AI and Microsoft Foundry, behind an LLM gateway, or with telemetry turned off</li>
<li>[VSCode] Fixed one cause of sessions failing to start with "Subprocess initialization did not complete within 60000ms": time a SessionStart command hook spends running no longer counts toward the limit, up to 10 minutes in total</li>
<li>[VSCode] Fixed a session closed while it was starting keeping its Claude Code process running until the start ended</li>
<li>[VSCode] Fixed a mod's drawings disappearing from a long-open panel until the next turn on machines that also run an older Claude Code</li>
<li>[VSCode] Fixed Past conversations hiding sessions when <code>claudeCode.claudeProcessWrapper</code> is set</li>
<li>[VSCode] Changed background sub-agents to show as one status line under their Agent card instead of streaming every step into the chat; the full transcript stays in /tasks</li>
<li>[Cloud sessions] Fixed folders in the composer's @ list showing no name in cloud sessions, where picking one added only a space instead of a mention</li>
<li>[Claude Tag] Fixed Claude going silent in a thread when its channel becomes shared across Enterprise Grid workspaces mid-task; it now posts a one-time note to @-mention it in a new thread</li>
<li>[Claude Tag] Fixed <code>@Claude !fork</code> typed outside a thread getting no visible reply; Claude now shows you a private note saying to run it from inside a thread</li>
<li>[Code Review] Added review levels to Code Review: Owners choose Quick, Standard (the default), or Deep for the organization, and can give individual repositories their own level</li>
<li>[Code Review] Added an option in Code Review admin settings to review every repository in a GitHub organization, including ones added later, without selecting them one by one</li>
<li>[Code Review] Fixed pull requests opened within a minute or two of an admin turning on Code Review being silently skipped; they are now retried and reviewed</li>
</ul>
