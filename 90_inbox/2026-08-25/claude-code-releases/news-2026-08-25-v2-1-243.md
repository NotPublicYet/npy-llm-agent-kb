## Summary
<h2>What's changed</h2>
<ul>
<li>Added a Loops breakdown to <code>/usage</code>: per-loop run count, total tokens, tokens per run, and last run, so runaway or chatty <code>/loop</code> tasks are easy to spot</li>
<li>Added <code>modelPicker</code> setting: curate the <code>/model</code> picker with an ordered, labeled list of models (any id spelling, including Vertex/Bedrock ids), appended to or replacing the built-in lineup</li>
<li>Added <code>promptCacheTtl</code> and <code>subagentPromptCacheTtl</code> settings so API-key and cloud-provider users can keep a 1-hour prompt cache on the main conversation while subagents stay at 5 minutes</li>
<li>Added <code>modelPricing</code> managed setting so an organization's contracted per-model rates and discount multiplier are used for <code>/cost</code>, the status line, and telemetry cost figures instead of list price</li>
<li>Added a keyless sign-in under <code>/login</code> → Anthropic Console: "Sign in with your Console account" (recommended) alongside creating an API key, so organizations that don't allow API keys can sign in</li>
<li>Added a <code>Skipped sources</code> line to <code>/status</code> that lists managed settings sources (for example <code>managed-settings.json</code>) present but not applied because a higher-precedence managed source is active</li>
<li>Added a <code>managed</code> marker in <code>/mcp</code> and <code>/plugins</code> on claude.ai connectors whose authentication is managed by your organization</li>
<li>Added a tip pointing claude.ai users who haven't connected GitHub for Claude Code on the web to <code>/web-setup</code></li>
<li>Added a <code>/status</code> line showing whether GitHub is connected for Claude Code on the web (Pro/Max), pointing to <code>/web-setup</code> when it isn't</li>
<li>Added the model (and effort level) each subagent ran on to <code>/tasks</code> and the agent detail dialogs</li>
<li>Fixed remote MCP servers in non-interactive (<code>-p</code>) and SDK sessions never recovering after a dropped connection; they now reconnect automatically or report as failed</li>
<li>Fixed MCP server sign-in started from the desktop app failing with "Invalid redirect URI" on servers that support client ID metadata documents (for example Linear)</li>
<li>Fixed auto mode staying unavailable at startup when a temporary server-side disable was cached and later flag fetches failed</li>
<li>Fixed auto mode tool calls being denied as "temporarily unavailable" after about a minute of waiting when the API was briefly overloaded and asked the client to retry</li>
<li>Fixed the <code>/model</code> picker silently ignoring an Ultracode selection; picking Ultracode now applies it to the current session</li>
<li>Fixed <code>/resume</code> only listing the 50 most recent sessions; the picker now loads more as you scroll</li>
<li>Fixed cloud sessions resuming after a mid-turn restart with a pending hook or background-task notification re-sent as the prompt instead of the normal continuation message</li>
<li>Fixed cross-session messaging silently turning off inside user namespaces and rootless containers after the 2.1.232 socket-directory hardening</li>
<li>Fixed text that hangs outside its container (for example the sign-in URL in <code>/login</code>) losing its leading columns when another part of the screen repaints</li>
<li>Fixed <code>spellcheck</code> not underlining a misspelled word typed directly after an emoji</li>
<li>Fixed background subagents not waking when their last background Bash task completes</li>
<li>Fixed sessions going silent for 10+ minutes when the Anthropic API never starts a response: the request now times out after ~3 minutes, retries once, then shows <code>API Error: No response from API</code></li>
<li>Fixed auth, model-availability, and other client-generated error messages rendering like model output instead of as error lines</li>
<li>Fixed workload identity federation in CI: processes in one job share the exchanged token instead of re-exchanging the single-use token; a rejected exchange fails fast with the server's message</li>
<li>Fixed server-managed <code>companyAnnouncements</code> not showing at startup in a session that began with signing in (for example the first launch after <code>/logout</code>)</li>
<li>Fixed hook <code>if</code> conditions like <code>Bash(cat *)</code> firing on unrelated Bash commands when the command contained <code>$()</code> or backtick command substitution followed by more arguments</li>
<li>Fixed plugin dependencies declared with a <code>marketplace</code> field never resolving when both plugins are loaded together via <code>--plugin-dir</code></li>
<li>Fixed <code>/reload-plugins</code> keeping the LSP tool after the last LSP plugin is disabled; it now also warns before an LSP plugin change that would re-read the conversation</li>
<li>Fixed <code>--agents</code> silently ignoring invalid JSON or invalid agent definitions; it now exits with a clear error, like <code>--mcp-config</code></li>
<li>Fixed <code>/status</code> showing "Found invalid entries in: ." with no filename when <code>~/.claude.json</code> has an invalid MCP server entry</li>
<li>Fixed <code>/clear</code> removing the <code>/rename</code> session name from the prompt bar even though the name was kept for the new session</li>
<li>Fixed Ctrl+R history search and up-arrow history breaking when <code>~/.claude/history.jsonl</code> contains a malformed entry</li>
<li>Fixed Ctrl+[ not leaving vim INSERT mode in terminals that encode modified keys (modifyOtherKeys / kitty protocol)</li>
<li>Fixed the local IDE connection being routed through <code>HTTPS_PROXY</code> (and sometimes failing) when <code>localhost</code> was listed in <code>NO_PROXY</code> but not lowercase <code>no_proxy</code>; both casings are now honored</li>
<li>Fixed sandbox network-violation details being dropped from the Bash tool result when the blocked command still exited 0 (for example <code>curl</code> printing the proxy's 403 page)</li>
<li>Fixed the status line <code>rate_limits</code> fields and <code>/usage</code> still showing a rate-limit window's pre-reset usage percentage after the window reset while the session was idle</li>
<li>Fixed <code>claude --teleport &lt;session&gt;</code> exiting on uncommitted changes instead of offering to stash them and continue, as the session picker already does</li>
<li>Fixed <code>/web-setup</code> repeatedly asking you to log in when an older GitHub CLI (without <code>gh auth token</code>) was already authenticated</li>
<li>Fixed Claude in Chrome losing its connection to Claude Code after an auto-update cleaned up the version it was set up with; the native host now launches via the stable <code>claude</code> launcher</li>
<li>[VSCode] Fixed sessions started before feature flags were first fetched (for example right after install) opening in the default permission mode instead of auto mode or your configured default mode</li>
<li>[VSCode] Fixed Focus view sections you expanded collapsing on their own during subagent tool activity</li>
<li>Improved startup time: sandbox and MCP bring-up no longer block the first frame, bare launches skip subcommand registration, and workflow discovery, settings, and trust-store work is cheaper</li>
<li>Improved native install and auto-update download size: the binary is now zstd-compressed (about 75 MB instead of 340 MB on Linux x64)</li>
<li>Improved attribution of usage telemetry to your organization for sessions that authenticate with <code>ANTHROPIC_AUTH_TOKEN</code> directly against the Anthropic API, so its data-handling settings apply</li>
<li>Improved native binary size: about 2 MB smaller by storing the bundled skill and prompt text more compactly</li>
<li>Improved memory usage of native builds: code is now loaded on demand instead of keeping the whole bundle resident (roughly 40–70 MB less memory per session)</li>
<li>Improved peak memory usage in long-running sessions (the runtime now garbage-collects sooner as the heap grows)</li>
<li>Improved <code>/login</code> over SSH: the sign-in URL appears immediately, pressing <code>c</code> reports how the URL was copied instead of always claiming success, and a hint explains how to select text in fullscreen</li>
<li>Improved the error when effort <code>xhigh</code>/<code>max</code> is used with thinking turned off: it now names the level, the setting that disabled thinking, and <code>/effort high</code> as the fix</li>
<li>Improved <code>/loop</code>: consecutive wake-ups where Claude has nothing to do now fold into a single line in the terminal instead of printing each one</li>
<li>Changed the sandboxed Bash tool prompt to no longer list allowed network hosts, so Claude attempts requests (and you can approve new hosts) instead of assuming unlisted hosts are blocked</li>
<li>Updated the <code>/model</code> picker and the bundled <code>claude-api</code> skill to show Sonnet 5's $2/$10 per Mtok pricing as its standard list price rather than a limited-time promo</li>
<li>Changed computer use on macOS so clicking the desktop, Dock, or a Finder window requires granting Finder via the access dialog, like any other app</li>
<li>Changed <code>/model</code>, <code>/fast</code>, and <code>/effort</code> to also run immediately instead of queueing until the turn ends on Bedrock, Vertex, and Foundry and when telemetry is disabled</li>
<li>Fixed <code>claude remote-control</code> exiting and stranding attached Remote Control sessions when the server drops its environment mid-session; it now recovers</li>
<li>Fixed Remote Control sessions served by <code>claude remote-control</code> sometimes getting stuck after it was stopped and restarted, for Team and Enterprise members without an admin or owner role</li>
<li>Changed the cross-session messaging inbox socket to close connections that send no complete line within 30 seconds; scripts posting to it should connect once their data is ready</li>
<li>Improved the notice when resuming a conversation whose Remote Control is held by another terminal: it now says sessions on other machines can't be seen from, or reach, this one</li>
<li>[VSCode] Improved history trimming in long sessions: older tool-activity rows are dropped first so your messages and Claude's replies stay visible</li>
<li>[VSCode] Improved attribution of the extension's own usage telemetry to your organization when you are signed in with a Claude account, so its data-handling settings apply</li>
</ul>
