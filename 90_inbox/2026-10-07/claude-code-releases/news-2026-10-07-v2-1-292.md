## Summary
<h2>What's changed</h2>
<ul>
<li>Added <code>--marketplace &lt;source&gt;</code> to <code>claude plugin install</code>: adds the marketplace if needed, under the same policy checks as <code>claude plugin marketplace add</code>, then installs the plugin from it</li>
<li>Added an <code>effort</code> parameter to the Agent tool, so Claude runs a sub-agent at the effort level you ask for</li>
<li>Added <code>CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS</code> environment variable to set a longer base delay for the backoff when retrying an overloaded (529) request</li>
<li>Added <code>prompt.autocomplete</code>, an event a mod hooks to add its own rows to the prompt box's autocomplete list</li>
<li>Added prompt caching to <code>$.model.complete</code> for mods: <code>prompt</code> and <code>system</code> take blocks of text, and <code>cache: true</code> on a block caches the request up to it</li>
<li>Added workflow agents to the <code>agent.spawn</code> mod hook, with their run and index, so a mod can refuse them</li>
<li>Fixed subagent definitions with <code>permissionMode: auto</code> entering auto mode when auto mode is unavailable (disabled by settings, circuit breaker, or a model that doesn't support it)</li>
<li>Fixed sandboxed commands being able to read the staged file copies of <code>/ultrareview</code> uploads under <code>~/.claude/seed-admin</code></li>
<li>Fixed a managed sandbox read-deny path (and user ones beside it) that appears or re-points mid-session not dropping project grants inside it or ending credential injection from files it covers</li>
<li>Fixed a notebook or PDF read on macOS and Windows being able to return a file outside what was approved, through a link swapped in mid-read</li>
<li>Fixed a tampered on-disk cache of server-managed settings being able to switch off or unseat the built-in policy plugin while the settings fetch failed</li>
<li>Fixed <code>rm -rf</code> on the 8.3 short name or another alternate Windows spelling of the home folder or a drive not being treated as removing it</li>
<li>Security: Fixed PreToolUse hook approvals and auto mode bypassing the permission prompt for file reads from network (UNC) paths</li>
<li>Fixed a skill's or slash command's <code>allowed-tools</code> rule coming back in a later turn when you leave auto mode or plan mode partway through that turn</li>
<li>Fixed <code>NO_PROXY</code> being ignored for Claude Code's own API requests (sign-in, policy, feedback, artifacts) when <code>HTTPS_PROXY</code> is set</li>
<li>Fixed an MCP tool with a name longer than 128 characters making every request fail; that tool is now left out and an MCP error names it</li>
<li>Fixed <code>claude plugin</code> commands such as <code>marketplace add</code> and <code>install</code> running before an organization's managed settings had loaded on a first run</li>
<li>Fixed one-shot <code>claude -p</code> and Agent SDK runs stopping a background command 5 seconds after the final result, and one-shot <code>claude -p</code> runs dropping a scheduled wakeup; both are now waited for</li>
<li>Fixed plan mode not being restored when resuming a session from the <code>claude --resume</code> session picker or with <code>/resume</code></li>
<li>Fixed saved scheduled tasks created after <code>/resume</code>, <code>/branch</code> or <code>/clear</code> never firing, and saved tasks ignoring later creates and deletes after two writes to the tasks file milliseconds apart</li>
<li>Fixed a background session's <code>/loop</code> silently stopping when the session's process restarted (for example after a crash), because its pending wakeup was lost</li>
<li>Fixed Grep and Glob reporting no matches when the file or folder they were given could not be read; Claude now retries once or tells you</li>
<li>Fixed the Read tool returning only the first entry, with no error, when a PDF's <code>pages</code> was a list such as "6,9,15"; it now returns an error saying to read each page or range separately</li>
<li>Fixed @-mentioned text files over 256KB being left out silently: Claude is now told the file's size and to read it in portions</li>
<li>Fixed the usage limit alert repeating once per background agent when agents failed on a limit that had already stopped the main conversation</li>
<li>Fixed Remote Control viewers seeing an empty subagent pane for background subagents in sessions hosted by the desktop app or an IDE</li>
<li>Fixed cross-session delivery notices showing two sessions with similar names as one recipient, and the expiry notice blaming the desktop app when a terminal session let the message lapse</li>
<li>Fixed Send now in the desktop app ending the subagent a turn was waiting on when another message was already queued</li>
<li>Fixed <code>/bug</code>, <code>/share</code> and <code>/feedback &lt;text&gt;</code> starting over after Ctrl+O or Ctrl+Z while a report was being sent, and closing as cancelled after it had been sent</li>
<li>Fixed <code>/remote-env</code> replacing your saved default environment when you pressed Enter right away: the list now opens on your default, and no row has a check mark when no default is in effect</li>
<li>Fixed some pasted text reaching Claude as typed text when several pastes overlapped in one prompt</li>
<li>Fixed vim mode leaving the cursor past the end of a line, j/k losing their column on shorter lines, and <code>f</code>/<code>t</code>/<code>F</code>/<code>T</code>/<code>;</code>/<code>,</code> jumping to, or deleting up to, a match on another line of the prompt</li>
<li>Fixed <code>/add-dir</code> path box letting Shift+Enter or a paste add a line break, and treating fast-typed "tab", "up" or "down" as those keys</li>
<li>Fixed fast typing, input-method text and decomposed accents being dropped while a prompt footer row was selected, and <code>!</code> leaving the row selected</li>
<li>Fixed fullscreen mode sending a full-screen clear on every window resize and Ctrl+L when iTerm2 is detected, which may be what filled iTerm2's scrollback with stale pages</li>
<li>Fixed a spurious "could not be examined" note for @-words that name no file when a Read deny rule is set and the working directory is under a symlink</li>
<li>Fixed "instruction file not loaded" lines going stale or missing after <code>/cd</code> or a permission change, and added a transcript line when a nested one isn't loaded</li>
<li>Fixed a compaction summary that repeated <code>/name</code> letting Claude invoke a skill that is reserved for the user</li>
<li>Fixed Write, Edit, NotebookEdit and LSP rows, and single Read, Grep and Glob rows, hiding why a mod denied the call: the row now shows the reason</li>
<li>Fixed a cloud session showing a turn that never ended when its worker was stopped just as the turn finished</li>
<li>Fixed cloud sessions with a large transcript sometimes asking for a permission again after it was approved</li>
<li>Fixed scheduled tasks and other queued notifications being lost in cloud sessions when a message was retried or edited while Claude was reading them</li>
<li>Fixed cloud sessions forgetting the thinking setting chosen in the client when the session's container restarted</li>
<li>Fixed Cowork cloud sessions saying a proxy blocked artifacts when Anthropic couldn't confirm the organization's settings</li>
<li>Fixed plugins whose hooks module makes many <code>$.state</code> calls through one const taking minutes to load or validate</li>
<li>Fixed <code>claude plugin validate</code> listing a matcher or state value for a hooks module that the engine reads from elsewhere</li>
<li>Fixed <code>claude plugin validate</code> listing a <code>$.state</code> value read through a top-level <code>var</code> that was declared again or reassigned; such a module is now refused</li>
<li>Fixed a plugin's served <code>$</code> method restarting the hook origin, which could run a guard hook with a <code>.catch</code> above it again without end</li>
<li>Fixed plugin interface calls made while the plugin hooks worker restarts running without the hooks other plugins put on them</li>
<li>Fixed a mod's <code>config.set</code>, <code>state.set</code>, <code>env.set</code> or <code>agent.spawn</code> hook that denies after calling <code>next(e)</code> being answered as a refusal: the hook is now reported as failed, by name</li>
<li>Fixed <code>/theme</code>, the <code>/config</code> Theme menu and the first-run theme step saving a theme before a plugin's <code>config.set</code> hook was asked</li>
<li>Fixed a plugin's <code>tool.check</code> hook answering allow running a tool that requires your answer (a question, a plan approval) without showing its dialog</li>
<li>Fixed a mod's start-up prompt, command or subagent being queued a second time when the hooks worker was replaced</li>
<li>Fixed a mod's hook that called <code>next(e)</code> and then failed while the turn was interrupted letting the call through; the call is now rejected</li>
<li>Fixed a plugin's prompt drop or setting deny being ignored when its reason was longer than 4,096 characters</li>
<li>Fixed an organization's plugin being unloaded on its own reload, or after another plugin crashed, when it returned a <code>$</code> name that a user-installed mod had added; the mod is now unloaded instead</li>
<li>Fixed tool calls made while the plugin hooks worker restarts being answered without the plugins' permission hooks</li>
<li>Fixed plugin <code>tool.call</code> hooks seeing some tool calls before misnamed parameters were repaired; a hook now sees the arguments the tool will run with</li>
<li>Fixed a mod's guard hook with a <code>.catch</code> being skipped silently for calls another mod's hook makes beneath the guard's own <code>$</code> call; its <code>.catch</code> is now asked</li>
<li>Improved startup of <code>claude -p</code> and SDK sessions: the first turn no longer waits for HTTP and SSE MCP servers to answer <code>resources/list</code></li>
<li>Improved rendering speed of long bulleted or numbered replies: they stream, resize and re-open in the transcript (ctrl+o) much faster</li>
<li>Improved Ctrl+C draft recovery: a cleared prompt now stays reachable with Up after a slash command or a sent message</li>
<li>Improved hook output handling: <code>&lt;system-reminder&gt;</code> tags written in a hook's output are escaped before they reach Claude</li>
<li>Improved tool input handling: Grep accepts <code>file_path</code> for <code>path</code>, and Write, WebFetch and Read ignore a few stray parameters instead of failing the call</li>
<li>Improved the steps shown when a marketplace declared in a settings file has a name that looks like an official Anthropic marketplace</li>
<li>Improved sandbox auto-allow: with strict sandbox mode set in user, managed or --settings settings, an interpreter command with an env var prefix like <code>FOO=bar python3 app.py</code> runs unprompted</li>
<li>Improved the Artifact tool's listing: Claude now sees how many published artifacts you have and can list up to 200 at once instead of 50</li>
<li>Improved cloud sessions after a restart: Claude is now told which stopped background agents it can resume by id</li>
<li>Improved the Claude in Chrome message in claude.ai cloud sessions when the browser can't be reached: Claude is now told it may continue with alternatives if the user prefers</li>
<li>Improved the /focus tip: it now invites you to try focus view mid-turn and shows how to switch back</li>
<li>Improved startup with local (stdio) MCP servers that ignore the newer protocol check: after one slow connect they are remembered for 7 days and connected the older way without the wait</li>
<li>Changed local (stdio) MCP server connections to negotiate protocol version 2026-07-28 by default on every install, including Bedrock, Vertex and Foundry; <code>MCP_PROTOCOL_NEGOTIATION=legacy</code> opts out</li>
<li>Changed <code>claude plugin test</code>: a failed <code>expect</code> inside a hook the test registered, or a stub answer the engine refuses, now fails the test instead of passing silently</li>
<li>Changed usage limit messages to write claude.ai settings links with https:// so terminals and apps can make them clickable</li>
<li>Changed scheduled and Run now routine runs to publish a new artifact only you can see without asking for approval; artifacts that request connectors or other access still ask</li>
<li>Changed agent names to allow at most 256 characters: a longer one is rejected, and a skill's or a plugin file's <code>name</code> longer than that is ignored</li>
<li>[Cloud sessions] Fixed routine runs occasionally staying listed as running for hours after they had finished</li>
<li>[Cloud sessions] Fixed editing or duplicating a routine turning off its push notifications when the routine had no saved notification setting</li>
<li>[Cloud sessions] Fixed SVG, HEIC, TIFF and other less common image files failing to attach; they now attach as regular files</li>
<li>[Cloud sessions] Fixed approval prompts offering "Always allow" for connector tools that an organization set to require approval; the choice had no effect</li>
<li>[Remote Control] Fixed the first message of a new Remote Control session started from claude.ai/code accepting only images; it now accepts PDFs and other files like later messages</li>
<li>[Claude Tag] Added an Edit button to the Allowed domains card on a channel's Configure page, so Enterprise admins can open the access bundle that sets the channel's domains</li>
<li>[Claude Tag] Fixed replies sent in a Slack thread while Claude was still on its first request there being held until that request finished, or missed when sent seconds apart</li>
<li>[Claude Tag] Fixed Slack threads woken only by GitHub pull request activity or a routine staying on their original model after an admin changed the channel or workspace default model</li>
<li>[Claude Tag] Fixed Claude sometimes posting a spend limit notice in Slack when the real cause was that your organization had run out of usage credits</li>
<li>[Claude Tag] Fixed a session hanging until interrupted when a permission prompt that can't be answered from Slack was denied automatically</li>
<li>[Claude Tag] Improved <code>@Claude !status</code> in a channel to say when Claude has stopped reading its untagged messages, why, and that an @-mention starts it reading again</li>
<li>[Claude Tag] Changed the first message of a Slack thread continued with <code>!fork</code> to a card showing where it came from, the request, and who asked, with a link to the original thread</li>
<li>[Claude Tag] Changed the organization-wide and default spend limit boxes on Claude Tag's spend limits page in admin settings to save only when you press Save or Enter, not when you click away</li>
<li>[Code Review] Added the period's total with its change from the previous period, and a breakdown by repository, to the PRs reviewed chart in Code Review analytics</li>
<li>[Code Review] Fixed a queued review failing when the pull request moved to a new base branch and the old one was deleted; the commit is now re-queued for review</li>
<li>[Code Review] Fixed reviews ignoring a CLAUDE.md's rules when the pull request edits that file; reviews now use its version from the base branch</li>
</ul>
