## Summary
<h2>What's changed</h2>
<ul>
<li>Added <code>onFailure: "block"</code> for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through</li>
<li>Added Program Status Protocol (OSC 7501) support: terminals that implement it can show whether Claude Code is working, waiting on you, or done</li>

<li>Added a "Backgrounding cancelled" message when you stop the turn while <code>←</code> is waiting for the current tool to finish</li>
<li>Added an optional <code>models</code> list to every Claude apps gateway upstream: only the listed models are sent there, on failover too, and one <code>*</code> in an entry is a wildcard</li>
<li>Added support for <code>forceLoginMethod: "gateway"</code> and <code>forceLoginGatewayUrl</code> in your own user settings on machines with no managed settings, so <code>/login</code> opens on that Claude apps gateway</li>
<li>Added advice to <code>claude plugin validate</code> when a plugin's README has no install line: it prints the line to paste and never changes the exit code, even with <code>--strict</code></li>
<li>Added <code>upstream_request_id</code> to the Claude apps gateway's <code>inference</code> audit event: the request ID from Amazon Bedrock, the Anthropic API or another upstream, for support cases</li>
<li>Added <code>$.ui.notify</code> for mods: raises a native notification through your own notification setting and says which channel sent it</li>
<li>Added children to a mod's <code>Button</code>: strings and <code>Text</code>, so a row of a list is one pressable with a chip or a dim detail inside</li>
<li>Added <code>CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS</code> to limit how long unattended retry mode (<code>CLAUDE_CODE_RETRY_WATCHDOG</code>) waits out 429 and 529 errors</li>
