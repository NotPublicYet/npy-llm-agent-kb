## Summary
<h2>What's changed</h2>
<ul>
<li>Added a record of your answer when Claude Code asks to turn on the mods it writes in a session</li>
<li>Added <code>assume_role</code> on <code>mantle</code> upstreams of the Claude apps gateway, for a role in another AWS account and for per-developer AWS cost attribution</li>
<li>Added an <code>effort</code> option to a mod's <code>$.model.fork</code>, so a quick side job can run at <code>low</code> whatever effort the session uses; the result reports the effort sent</li>
<li>Added the date a stored claude.ai sign-in ends to <code>claude auth status</code> (<code>loginExpiresAt</code>) and to <code>claude -p</code> JSON results (<code>credential_expires_at</code>)</li>
<li>Added a one-line stderr warning to <code>claude -p</code> text output, starting 10 days before a stored claude.ai sign-in ends</li>
<li>Fixed <code>--continue</code> sometimes losing the earlier conversation after a malformed tool call's retries ran out (regression in 2.1.314)</li>
<li>Fixed macOS sessions with many running Bash commands stalling while memory grew</li>
<li>Fixed permission prompts being answered by keys typed just after sending a message, or before a slow prompt appeared</li>
<li>Fixed <code>/logout</code>, <code>claude auth logout</code> and <code>claude mcp remove</code> reporting success, and changes to trust, consent or MCP settings being dropped with no word, when the config file could not be updated on a shared network home directory</li>
<li>Fixed jobs exiting with <code>Not logged in</code> when another terminal or host signs in again to the same account and organization on the same home</li>
<li>Fixed <code>claude mcp add</code> and <code>remove</code> writing the config without its lock: they now wait for it or exit 1, though another job's save can still replace a saved server</li>
<li>Fixed <code>claude plugin</code> commands exiting before a slow token refresh was saved, which could sign you out on the next run</li>
<li>Fixed <code>claude plugin validate</code> passing a custom-named marketplace file that <code>claude plugin marketplace add</code> rejects</li>
<li>Fixed stdio MCP servers that exit on the version probe being re-probed on every start; a server that dies in under 3s for its own reason is also pinned to the legacy handshake for 7 days</li>
<li>Fixed sessions being refused at startup by an <code>allowedProviders</code> list that another login on the same machine had stored</li>
<li>Fixed idle compaction replacing a conversation with a reply that was not a summary</li>
<li>Fixed the "Now using usage credits" notice reappearing about every 30 seconds while a background subagent is running</li>
<li>Fixed custom slash commands that fail, or that only Claude can invoke, printing nothing in <code>claude -p</code> and SDK sessions</li>
<li>Fixed <code>claude -p</code> and Agent SDK sessions reporting success when an API error cut off a reply while a mod hooked <code>turn.step</code></li>
<li>Fixed a message sent right after a model change still running after Stop in headless sessions: Stop now cancels or stops it as it would a queued message</li>
<li>Fixed a deleted session transcript being re-created with its last prompt when an idle non-interactive session exited</li>
<li>Fixed <code>claude remote-control</code> hosts, the background daemon and self-hosted runners failing to start new sessions (<code>spawn ENOENT</code>) after an update or version cleanup removed the binary of a still-running process</li>
<li>Fixed a running Claude Code process owned by another user (for example one left by <code>sudo claude</code>) being treated as dead by version cleanup, which could delete its binary</li>
<li>Fixed <code>/remote-control</code> showing a session as available after a failed connection</li>
<li>Fixed <code>/design revoke</code> reporting success when the request failed with a 404</li>
<li>Fixed a shell command approved after a self-hosted runner or cloud session restart running in the session's start folder, not the folder it was asked in; if that folder can't be entered, it is not run</li>
<li>Fixed Claude not being told when an approved connector tool was unavailable after a cloud session restart</li>
<li>Fixed cloud sessions being stopped in the middle of a turn when the service refuses uploads for several minutes</li>
<li>Fixed variables a <code>Setup</code> hook writes to <code>CLAUDE_ENV_FILE</code> not reaching the Bash tool in some cloud sessions</li>
<li>Fixed the iPhone app showing a cloud session's turn as finished while it kept running, after a response was cut off at a tool call or a refused image or document was removed</li>
<li>Fixed a restarted session re-sending a message that failed with an API error, ahead of the newer message waiting behind it</li>
<li>Fixed a restarted session dropping its interrupted turn when the restart came right after Claude read a large image or retried a tool call</li>
<li>Fixed every connection failing when the <code>NODE_EXTRA_CA_CERTS</code> file is empty, not PEM, or starts with a damaged certificate: readable certificates are now used, with a warning on stderr</li>
<li>Fixed workflows re-running finished agents when resumed after a usage limit</li>
<li>Fixed <code>/mcp</code> in cloud sessions counting tools the model can't use; a server's row now shows how many of its tools are available</li>
<li>Fixed a duplicate notification when Claude left the status field out of a PushNotification call</li>
<li>Fixed the error for a too-large image in a request with more than 20 images always saying the limit was 2000px; it now shows the API's limit</li>
<li>Fixed the runtime in background shell details not updating while the dialog is open</li>
<li>Fixed a mod's <code>turn.step</code> hook making a stopped reply finish as a success in headless runs</li>
<li>Fixed retention cleanup leaving a home that only runs <code>claude -p</code> with no <code>~/.claude.json</code> backup: it now takes a fresh backup before deleting the last good one</li>
<li>Fixed the stored login being replaced by an empty file when a network home directory has no room left for data but still takes new files</li>
<li>Fixed tokens from <code>setup-token</code> being refused at start on machines with <code>forceLoginOrgUUID</code>, when the token belongs to a permitted organization</li>
<li>Fixed non-interactive launches replacing a <code>~/.claude.json</code> that isn't valid JSON with defaults; the start now fails, says how to restore the file, and leaves it as is (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5178986556" data-permission-text="Title is private" data-url="https://github.com/anthropics/claude-code/issues/87551" data-hovercard-type="issue" data-hovercard-url="/anthropics/claude-code/issues/87551/hovercard" href="https://github.com/anthropics/claude-code/issues/87551">#87551</a>)</li>
<li>Fixed an empty <code>~/.claude.json</code> with no backup being reported as corrupted; Claude Code now starts as it does when the file is missing</li>
<li>Fixed the restore command printed for a damaged or missing <code>~/.claude.json</code> naming an empty or cut-off backup, or failing on a read-only file</li>
<li>Fixed the sign-in failure when a stored claude.ai login reaches its time limit: it now says so, and in <code>claude -p</code> names <code>claude auth login</code> and <code>claude setup-token</code></li>
<li>Improved how <code>~/.claude.json</code>, settings files and the stored login survive saves on shared network home directories: they are less often deleted, briefly emptied or replaced by a near-empty or older copy</li>
<li>Improved sessions on network file systems to look again when the configuration file is wrongly reported as missing, so fewer start without your MCP servers and trusted folders</li>
<li>Improved MCP tool errors: a call made before the tool is loaded now returns its input schema</li>
<li>Improved the reliability of git commits and pull request creation when the Bash tool runs macOS's built-in <code>/bin/bash</code></li>
<li>Improved "Ask your admin for more usage" in the usage limit menu to send the request in one step</li>
<li>Improved how fast remote sessions reconnect after a pause or sleep</li>
<li>Improved You should know toasts to say "try again" instead of "press 2", which only works in the terminal</li>
<li>Improved auto-update reliability: a brief network failure while verifying a release is now retried right away instead of waiting for the next check</li>
<li>Improved unattended runs (<code>claude -p</code>, SDK apps) to stop rewriting <code>~/.claude.json</code> on every run when nothing in it changed</li>
<li>Changed Claude Code to no longer install or update the IDE extension when started in an IDE terminal; use <code>/ide</code> from an outside terminal or your editor's extensions view</li>
<li>Changed subagents to stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time"</li>
<li>Changed background subagents to move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs</li>
<li>Changed subagent progress summaries on Bedrock, Vertex, Foundry, or with telemetry off: on a cold prompt cache, one can now wait up to 5 minutes for the subagent's pending response</li>
<li>Changed what a mod attaches at <code>prompt.submit</code> to stay in the user's turn rather than go out as a system message</li>
<li>Changed <code>deniedMcpServers</code> URL entries to also block Anthropic-provided servers whose upstream URL matches, and connectors in cloud sessions and on self-hosted runners, where the session is given the connector's own URL; otherwise deny a connector by name</li>
<li>Changed the <code>/permissions</code> rule details, built-in rules and delete confirmation views to use the standard dialog; pressing Ctrl+C twice there now goes back or cancels instead of quitting</li>
<li>Changed <code>/claude-api managed-agents-onboard</code> to give a new agent's built-in tools, and a quickstart template's MCP tools, the <code>auto</code> permission policy ("Judge risky actions") by default, matching the Claude Console; say "run without asking" to opt out</li>
<li>Removed the 2.1.288 fix that kept the model's earlier thinking when resuming a conversation started on 2.1.286 or earlier; that thinking can now be dropped</li>
<li>Gateway: Added a log warning when the Google access token from a federation (<code>external_account</code>) credentials file is about to expire</li>
<li>Gateway: Improved the log hints about <code>listen.trusted_proxies</code>: they now say to list only a proxy that adds the connecting address to <code>X-Forwarded-For</code> itself</li>
<li>Gateway: Improved the warning when AWS CountTokens fails on Amazon Bedrock: it says Claude Code, not the gateway, counts after the 501, and points at IAM only when AWS denies access</li>
<li>Self-hosted runner: Added <code>CLAUDE_RUNNER_SPAWN_REASON</code> to the orchestrator's spawn-runner hook environment: why Anthropic sent the request (e.g. <code>runner_lost</code>, <code>resumed</code>); unset when none was sent</li>
<li>Self-hosted runner: Added a startup warning when <code>--release-idle-session-min</code> is the last argument with no value (still ignored) or has a value of only spaces (still read as <code>0</code>)</li>
<li>Self-hosted runner: Changed the orchestrator's log lines: <code>ok session=…</code> now prints at every log level on stdout (was debug only, stderr) with <code>reason=…</code> after <code>jti=…</code>, and <code>nack session=…</code> ends its fields with <code>reason=…</code> after <code>retryable=…</code>; update scripts that match <code>retryable=true:</code> or <code>retryable=false:</code></li>
<li>Remote Control: Fixed a misleading "spawn error: ENOENT" when a session's working folder is missing; the error now names the folder</li>
<li>Remote Control: Improved the title a fork of a terminal fork is created with when the app doesn't set one: "Name (fork 2)"</li>
<li>[VSCode] Fixed a window whose sign-in the organization's settings refuse starting a new Claude Code process in the background every minute</li>
<li>[VSCode] Fixed a long word in the chat panel's error banner pushing its close button out of view</li>
<li>[VSCode] Improved the sign-in screen to show what Claude Code printed when its sign-in status check fails</li>
<li>[Cloud sessions] Added a No repository option: a cloud session on an Anthropic-hosted environment can now start without picking a repository</li>
<li>[Cloud sessions] Added the usual Chrome names to cloud sessions, so tools other than Playwright can find the built-in Chromium through google-chrome and CHROME_PATH</li>
<li>[Cloud sessions] Added a New session button to the card shown when a cloud session's environment was deleted, where the message box is hidden</li>
<li>[Cloud sessions] Fixed reading GitHub Actions logs in cloud sessions: <code>gh run view --log</code> and <code>gh api</code> log requests now get the log in most environments, not an unreachable redirect</li>
<li>[Cloud sessions] Improved most Create PR failure messages in cloud and Remote Control sessions: they now give the reason or a link to GitHub instead of saying Try again</li>
<li>[Cloud sessions] Changed connector search results to tell Claude that the search covers only part of the connector directory</li>
<li>[Remote Control] Fixed side-by-side checkouts of one repository looking identical in the environment menu's Remote Control rows; each now shows its own folder name</li>
<li>[Claude Tag] Fixed keyboard focus and screen reader announcements in Claude Tag admin setup; pressing Escape in the connect form no longer also closes the Add dialog</li>
<li>[Code Review] Improved the Code Review analytics page to retry once after a server or network failure, then show a Try again banner instead of empty cards</li>
</ul>
