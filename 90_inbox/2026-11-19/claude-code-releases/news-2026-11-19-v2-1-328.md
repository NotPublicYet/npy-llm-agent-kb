## Summary
<h2>What's changed</h2>
<ul>
<li>Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it</li>
<li>Added <code>"onFailure": "block"</code> for <code>mcp_tool</code> hooks, as for command and HTTP hooks: a hook whose call fails blocks the action</li>
<li>Added a warning when a message from a session that skips permission prompts may be held and dropped by a cloud session</li>
<li>Added a notice in <code>/status</code> and <code>claude doctor</code> when an OpenTelemetry exporter has no endpoint and its data would likely be lost</li>
<li>Added <code>CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME</code>, which lets a host stop <code>claude -p --resume</code> and <code>--continue</code> from running a tool call that a hook deferred</li>
<li>Added support for apps that embed Claude Code to switch on the policy plugin's <code>allowManagedModsOnly</code> option; an admin's managed settings still win</li>
<li>Added a startup warning to the Claude apps gateway when a policy's <code>maxEffortLevel</code> is not a valid effort level</li>
<li>Self-hosted runner: Added <code>--repository-folder</code> to name the folder that sessions use for a repository at <code>--capacity 1</code>, in place of its path under the base folder, which can't be a symbolic link</li>
<li>Self-hosted runner: Added a start-up warning when the host's settings.json sets a default permission mode that sessions ignore</li>
<li>Self-hosted runner: Added <code>--hook-label</code> to <code>claude self-hosted-runner orchestrator</code>, to hand chosen session labels to the <code>spawn-runner</code> hook</li>
<li>Self-hosted runner: Added <code>--metadata key=value</code> to <code>claude --environment</code>, to label a session for the <code>spawn-runner</code> hook</li>
<li>Self-hosted runner: Added <code>claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds</code> to the orchestrator's <code>/metrics</code>, so a re-opened session's wait can be told from a new one's</li>
